# Windows 桌面版 0.2.1 验证

日期：2026-10-13。本机 Windows x64；WebView2 Runtime 154.0.4258.62，SDK 固定为 1.0.4258.31。

## 已通过

- `pnpm run build:desktop` 使用本机 .NET Framework 编译器生成 Windows x64 单 EXE，978,944 字节；内嵌界面与运行组件，不捆绑整个浏览器。
- `pnpm run test:desktop` 将单个 EXE 复制到新的中文路径运行，资源自行展开，无需相邻源码、Node、pnpm 或 DLL 文件。
- 原生窗口加载离线页面，中文通知提取、人工核对、保存、页面重载、编辑、完成/恢复状态正常。含 HTML 标签的标题按文字显示。
- 同一数据目录的第二个实例退出，避免并行写入同一配置。
- 读取 8 条小程序格式记录并与桌面新建记录合并；桌面经原生文件保存桥接导出的 9 条记录可由小程序数据模块完整读取。
- 实际生成备份及日历文件；错误备份不改变已有记录，全部替换支持取消与确认。
- 完全关闭 EXE，再从同一目录启动，8 条记录仍保留。此项使用实际进程退出，不只刷新页面。
- 数据与帮助文案没有 JSON/API/AppID；820 像素宽下无水平溢出。大量待办在右侧列表内滚动，备份操作不在长列表末尾。
- 页面脚本异常 0，业务页面外部请求 0。测试开启离线模式；此结论不涵盖微软运行时自身的组件更新等进程行为。

运行摘要为 `desktop-v0.2.1.json`，已检查的截图为 `assets/previews/windows-desktop.png`、`windows-help.png`。全部模拟数据在 `.cache/desktop/qa/` 的独立目录，不进入交付包，也未改写微信和网页记录。

## 验证范围

文件测试调用真实 C# 保存与写入流程，但测试模式自动选择隔离目录；未自动操作原生“另存为”选择器或真实微信聊天文件选择器。其他电脑、缺少运行环境时的安装、实际日历软件导入、杀毒软件与 SmartScreen 提示未覆盖。当前 EXE 未做付费代码签名。

早期自动化在 WebView2 控件初始化前连接调试器，出现新页面等待调试器的情况。测试现先等待真实本地页面加载后连接，完整重启回归通过；普通双击运行没有调试端口。启动阶段的诊断日志只在测试模式启用。
