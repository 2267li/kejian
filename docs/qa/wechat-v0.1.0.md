## 模拟器：已修复并通过

用户扫码登录后，最初 CLI 和自动化端口正常，但页面白屏，App.getCurrentPage 不返回；2026-10-12 16:57 工具提示“模拟器长时间没有响应”。工具版本为 1.06.2308310，项目未固定基础库，`latest` 先后解析到不同版本，迁移后返回 3.17.3 时仍无法进入页面。

先将微信工具用户数据完整校验并迁移至 E 盘，消除原默认路径的空间限制。对照测试中，仅含文字和计数按钮的最小小程序使用本机已有 3.12.1 基础库能启动；课间也固定为 3.12.1 后，真实页面和操作恢复正常。结果证明当前组合下的可用修复，不据此认定其他微信版本均有同样问题，也不将超时提示直接归为业务死循环。未升级或重新安装微信工具。

真实模拟器发现并修复：Grid 默认最小内容宽度导致输入框横向溢出；微信 v2 默认按钮宽度覆盖完成按钮和全宽按钮。现已设置可收缩列宽、明确按钮尺寸和间距。

`tests/miniprogram-runtime.cjs` 在实际微信模拟器（320 CSS 像素宽）验证中文输入、日期组件 change 事件、识别日期与时间、切换标签保留草稿、保存、重开保持数据、完成、编辑已完成事项、帮助页和原生控件尺寸，未捕获到未处理异常。测试使用模拟数据，并在 finally 中恢复测试前的本地待办存储。截图已人工检查；不代表完成真实手机文件授权或系统日历验证。

运行摘要位于 `docs/qa/wechat-runtime-v0.1.0.json`，确认的截图位于 `assets/previews/wechat-*.png`。旧工具窗口被完全遮挡时，自动化截图回调可能超时；截图为可选项，设置 `KEJIAN_WECHAT_SCREENSHOTS=1` 并保持工具可见。此类截图超时与前述应用无法启动分别记录。

## 追加：表单底部按钮回归

用户截图暴露了此前截图未覆盖的草稿底部：取消按钮仍为微信 v2 默认宽度 184 CSS 像素，确认按钮只剩 54 像素，文字竖排使按钮高达 160 像素。现在操作行显式覆盖默认宽度，取消按钮按内容定宽，主按钮分配剩余宽度。

`pnpm run test:wechat:layout` 在基础库 3.12.1、320 CSS 像素宽的真实模拟器中通过：新建与编辑行按钮宽 60/178 像素，导入行 60/148 像素，分页按钮各 117 像素；全部高 44 像素，文字空间充足、水平对齐且无重叠或横向溢出。此脚本只改变渲染数据，最后恢复原页面与草稿，不调用保存方法、不修改待办存储。

已检查草稿底部和导入面板截图，分别存于 `assets/previews/wechat-draft-actions.png`、`assets/previews/wechat-import-actions.png`；运行记录见 `docs/qa/wechat-layout-v0.1.0.json`。这次补测不包含真机验证。

用户反馈示例按钮过宽、换行且错位。收通知区域现采用三列等宽示例按钮，将示例标签放在独立一行；主按钮明确字号、圆角和高度，说明改为两条简短文字。
